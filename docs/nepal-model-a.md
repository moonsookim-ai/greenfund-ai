## 이번 공개판의 결론

UNICEF는 영향 지역 전체에서 약 13,000가구의 식수·위생 지원 수요를 보고했다. 9월 3일 발표는 최소 22,000명의 아동 수요를 밝혔다. 물품 발송은 보고되지만 같은 지역·같은 가구집단의 지원 완료 가구 집계와 일치하지 않는다. 따라서 둘을 빼서 미지원 가구로 만들지 않는다.

WHO가 언급한 라수와·누와코트·다딩·고르카·타나훈·치트완 6개 지구를 초기 검토 대상으로 삼았다. 전체 피해지역을 망라하거나 피해 규모순으로 나열한 목록이 아니다. HEOC와 구호기관 자료로 피해 사실과 현장 확인 과제를 연결했다. 동일 기준의 가구 입력 30개는 미확인으로 남겨 두었고, **공식 점수와 순위는 산출 보류**한다.

환경재단의 다음 행동은 현지 파트너와 평가 구역·일자·지원 기준을 합의하고, 중복 제거한 수요·지원 기록을 확보하는 것이다. 데이터가 부족한 지역을 낮은 순위로 간주하지 않는다. 실제 구호 활동을 이 도구의 입력 완료까지 미루라는 뜻도 아니다.

## 입력 사전

### 첫 화면의 위성 사진과 주요 피해지역

첫 화면에는 ESA가 공개한 Sentinel-2 자연색 영상(홍수 전 8월 12일,
홍수 후 8월 27일)을 표시한다. 기본 화면은 홍수 후 영상이며, 이전 영상은
선택할 때 불러온다. 두 영상을 그대로 번갈아 보거나 겹쳐 비교할 수 있다.
사진의 날짜·출처·CC BY-SA 3.0 IGO 이용조건은 사진 옆과 이미지 폴더에
표시한다. 원본 JPEG에 지명·피해 경계·지원 순위를 임의로 덧그리지 않는다.

라수와·누와코트를 첫 화면에 배치한 근거는 [IFRC의 8월 26일 발표](https://www.ifrc.org/press-release/nepal-ifrc-releases-emergency-funds-flash-floods-leave-communities-isolated)에서 두 지역의 큰 피해가 보고됐기 때문이다.
이는 공개 근거에 따른 주요 피해지역 소개이며, 모델 점수나 지역 사이의
확정 순위가 아니다. 현재 시각의 접근성이나 미지원 가구 수를 단정하지 않는다.
`snapshot.json`의 `focus`에 선정 근거와 출처를, `imagery`에 영상 이력을 남긴다.
기존 공개 입력은 미확인 상태를 유지하며 두 지역에 임의의 점수를 부여하지 않는다.

연구책임자와 이메일은 사이트 하단의 작은 문의 문구로만 표시하고, 페이지
상단이나 공유 설명에 개인 이름을 넣지 않는다.

### 가구 입력 정의

집계 단위는 한 시점의 동일 평가구역 안에 있는 고유 가구다. 지역별 평가구역은 공통 조사 기준으로 정의한다. 이재민이 이동한 경우 기준일 현재 위치를 사용하고 여러 지구에 중복 집계하지 않는다. 피해 범위가 달라진 새 조사는 별도 버전으로 취급한다.

| 필드 | 정의 | 검증 |
|---|---|---|
| affected | 평가구역의 영향 가구 수 | 0 이상 안전한 정수 |
| severe | 영향 가구 중 주택이 거주 불능인 가구 수 | severe ≤ affected |
| needs | 같은 영향 가구집단 중 식수·위생 지원이 필요한 가구 수. 지원받은 가구도 분모에 유지 | needs ≤ affected |
| served | needs 중 합의한 최소 지원 범위·기간을 실제 충족한 가구 수 | served ≤ needs |
| vulnerable | needs 중 합의한 취약성 기준에 해당하는 고유 가구 수 | vulnerable ≤ needs |

취약성 기준에는 아동·고령자·장애인·임산부 등을 검토할 수 있지만 기준은 현장과 합의한다. 중복 조건에 해당해도 한 가구로 센다. 취약가구 중 지원 완료 비율을 별도로 반영하려면 추가 데이터와 모델 개정이 필요하다. 이 모델 V는 필요 가구 전체의 취약성 비율이다.

최소 지원 기준은 물품 이름만이 아니라 급수·위생 서비스의 범위와 지속 기간을 포함해 합의해야 한다. 물품 발송, 지원 약속, 진료 건수, 개인 수혜 건수는 `served`의 대체값이 아니다. 지원을 받아 필요가 해소된 가구를 `needs`에서 제거하면 분모와 `served`가 어긋나므로 금지한다.

확인된 0과 미확인 `null`을 구분한다. 한 항목이라도 미확인이면 점수·순위를 만들지 않는다. 빠진 항목을 제외하고 나머지 가중치를 재분배하지 않는다.

## 계산과 해석

```text
D = severe / affected
U = (needs - served) / needs
V = vulnerable / needs
score = 100 × (wD × D + wU × U + wV × V)
wD + wU + wV = 1
```

기본은 동일 가중치 1:1:1이다. 피해·공백·취약 중시 조합은 해당 항목에 2, 나머지에 1을 주고 정규화한다. 기본값은 현장 검증으로 최적화한 값이 아닌 공개된 정책 가정이다. 자료가 완전한 지역 사이에서 점수가 클수록 검토 우선순위가 높으며, 동점은 공동 순위를 부여한다. 표시 반올림 전 점수로 순위를 계산한다.

- `needs=0`이면 식수·위생 추가 지원 순위에 넣지 않는다. 다른 구호 수요가 없다는 뜻은 아니다.
- `needs=served`이면 추가 지원 순위에서 제외한다. 다음 평가일에 서비스 지속성을 재확인한다.
- 작은 지역에서 비율이 높게 나올 수 있다. 절대 미지원 가구 수를 함께 보며 점수에 비례해 예산을 나누지 않는다.
- 주거 불능 비율은 제한된 피해 지표다. 인명 피해·식량·교육·재건 전체를 설명하지 않는다.
- 접근성 미확인은 현장 확인 과제로 표시한다. 접근하기 어렵다는 이유로 자동 감점하지 않는다.
- 4개 가중치 조합의 최고·최저 순위는 민감도 범위이며 통계적 신뢰구간이 아니다. 누락된 지역과 측정 오차에 대한 불확실성은 여전히 남는다.
- 교차검증·정확도·구호 효과에 관한 성능 주장을 하지 않는다. 관측 결과로 보정한 예측 모델이 아니다.

## 공개 자료와 시나리오의 분리

`greenproof/web/nepal/data/snapshot.json`은 검토한 사실·출처·확인 위치와 미확인 입력을 담는다. 웹의 입력 폼은 별도 메모리 객체에만 저장하며 이 JSON을 수정하지 않는다. 서버로 전송하거나 브라우저 저장소에 보존하지 않는다. 다운로드에는 `USER_SCENARIO_NOT_OFFICIAL`, 평가 조건, 원본 입력, 가중치, 결과, 민감도를 함께 기록한다. 시험용 가상 숫자는 테스트 파일에만 있고 공개 화면에 미리 채우지 않는다.

첫 입력을 저장하면 공통 기준일·집계 기준·최소 지원 기준을 잠근다. 전체 초기화 후에만 새 기준으로 입력하도록 해 서로 다른 평가를 섞지 않는다. 비교는 저장한 지역만 대상으로 하며, 입력이 부족한 지역의 순위는 빈칸이다.

공식 데이터로 전환할 때는 각 필드의 `inputSources`와 `review.approved=true`, 공통 `review.asOf`, `review.cohort`를 작성한다. 코드는 유효한 날짜·명시적 승인·출처 문자열을 요구하고 날짜·집계 기준이 다른 지역끼리 비교를 막는다. 이 검사는 출처의 사실성 자체를 보증하지 않으므로 연구책임자가 원자료를 검토해야 한다. 오래된 자료는 최신으로 간주하지 말고 새 확인일로 갱신한다.

## 실행·검증·배포

정적 HTML/CSS/ES modules만 사용하므로 웹 빌드나 런타임 라이브러리 설치가 필요 없다. 모델은 같은 입력으로 같은 결과를 내는 순수 함수이고 외부 AI API를 호출하지 않는다. GPT-6 Astra는 연구·설계·구현 과정에 활용했다.

```sh
node --test tests/nepal-model.test.mjs
python tools/check_web.py
python -m http.server 4810 --directory greenproof/web --bind 127.0.0.1
```

계산 검증은 누락·0 구분, 잘못된 부분집합·가중치, 분모, 순위 동점, 순위 역전 민감도, 공개 근거 검토 조건, 실제 스냅샷의 빈 입력을 포함한다. 웹 검증은 문법·로컬 참조·브랜드·연락처·삭제한 바다 코드 참조를 확인한다.

기존 Cloudflare Pages 프로젝트는 `greenproof`이며 `greenfund.ai.kr`에 연결된다. `greenproof/web` 전체를 배포해 위성 검증과 배출 지도도 유지한다. 운영 브랜치는 `main`이다.

```sh
npx wrangler pages deploy greenproof/web --project-name greenproof --branch main --commit-hash <verified-sha> --commit-dirty=false
```

배포 후 `/`, `/emissions/`, `/nepal/` 및 모듈·JSON의 HTTP 상태, 브랜딩과 콘텐츠를 확인한다. `_headers`는 HTML·스냅샷 갱신과 JS MIME 형식을 지정한다.
